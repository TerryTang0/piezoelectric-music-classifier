# Piezoelectric Music Classifier

## Background

This project comes from my undergraduate research in the FLEX lab at **Purdue University**, where I worked on fabricating piezoelectric sensors and analyzing the electrical signals they generated[cite: 10].

The main question I wanted to explore was:

**Can the electrical response from a piezoelectric sensor be used to tell different types of music apart?**[cite: 10]

To test this, I fabricated the sensors, collected current signals while different songs were played, processed the signals in Python, and trained several machine-learning models to classify the music genre[cite: 10].

## Abstract

I fabricated **35 piezoelectric sensors** during this project[cite: 10]. Out of those, **3 sensors produced stable and usable signals** for further experiments[cite: 10].

Using these sensors, I collected **26 music recordings across six genres**[cite: 10]. The current generated by the sensor was measured using a low-noise current preamplifier and recorded through LabVIEW[cite: 10].

The raw signals were processed in Python using filtering, window segmentation, and feature extraction[cite: 10]. Each signal window was converted into 19 numerical features and evaluated using five machine-learning models[cite: 10].

To prevent data leakage, windows from the same song were kept together during cross-validation[cite: 10].

Among the five models, **Random Forest achieved the highest mean Macro F1 score of 0.4726 ± 0.0675**[cite: 10]. Across all out-of-fold predictions, it correctly classified **769 of 1,459 signal windows**, corresponding to an overall accuracy of **52.7%**[cite: 10].

## Sensor Fabrication

The sensors were fabricated using a flexible **Ecoflex substrate**[cite: 10].

The main fabrication steps were:

1. Prepare the Ecoflex base[cite: 10].
2. Add the liquid-metal electrode/bar to the Ecoflex[cite: 10].
3. Soak the device in a solution containing `H2SO4`, `Zn(NO3)2·6H2O`, and `H2O`[cite: 10].
4. Leave the device in the solution for approximately **6 hours**[cite: 10].

A total of **35 sensors** were fabricated, and **3 produced stable enough responses** for the music experiments[cite: 10].

## Code Structure

The analysis is divided into five Python files[cite: 10]:

- `labels.py` — assigns the genre and song ID from each filename[cite: 10]
- `loader.py` — reads the LabVIEW data and preprocesses the current signal[cite: 10]
- `features.py` — extracts numerical features from each signal window[cite: 10]
- `dataset.py` — builds the machine-learning dataset[cite: 10]
- `main.py` — trains and evaluates the classification models[cite: 10]

---

## Signal Processing Pipeline

The raw LabVIEW current signal first goes through signal preprocessing[cite: 10].

The DC offset is removed, followed by a **0.5–450 Hz Butterworth band-pass filter**[cite: 10].

Each recording is then divided into **5-second windows with 50% overlap**[cite: 10]. Nineteen features are extracted from every window and used as input to the machine-learning models[cite: 10].

The complete dataset contains[cite: 10]:

- **1,459 signal windows**[cite: 10]
- **26 original music recordings**[cite: 10]
- **19 features per window**[cite: 10]

The overall pipeline is[cite: 10]:

**Raw LabVIEW signal → Signal preprocessing → 5-second windows → Feature extraction → Dataset construction → Grouped cross-validation → Model comparison → Genre prediction**[cite: 10]

## Feature Engineering

For each 5-second signal window, I extract **19 features** that describe the amplitude, shape, timing, energy, and frequency distribution of the electrical signal[cite: 10].

### Amplitude and Energy

- RMS[cite: 10]
- Maximum amplitude[cite: 10]
- Crest factor[cite: 10]
- Signal-to-noise ratio[cite: 10]
- Log total power[cite: 10]
- Energy entropy[cite: 10]

These features describe the overall strength and energy of the current signal[cite: 10].

### Signal Shape

- Skewness[cite: 10]
- Kurtosis[cite: 10]
- Zero-crossing rate[cite: 10]

These features describe the shape and statistical distribution of the waveform[cite: 10].

### Pulse Timing

- BPM[cite: 10]
- Tempo variation coefficient[cite: 10]

These features are based on the spacing between detected electrical peaks[cite: 10].

The BPM value is treated as an estimate of the **electrical pulse rate**, rather than the exact musical BPM of the original song[cite: 10].

### Frequency-Domain Features

- Sub-bass band power: 5–35 Hz[cite: 10]
- Bass band power: 35–100 Hz[cite: 10]
- Mid-frequency band power: 100–250 Hz[cite: 10]
- High-frequency band power: 250–450 Hz[cite: 10]
- Sub-bass-to-mid ratio[cite: 10]
- Bass-to-high ratio[cite: 10]
- Spectral centroid[cite: 10]
- Spectral flux[cite: 10]

These features describe how the signal energy is distributed across different frequency ranges[cite: 10].

## Machine-Learning Models

I compared five machine-learning models[cite: 10]:

- Logistic Regression[cite: 10]
- k-Nearest Neighbors[cite: 10]
- Support Vector Machine[cite: 10]
- Gradient Boosting[cite: 10]
- Random Forest[cite: 10]

I selected these models to compare several different types of classification approaches[cite: 10].

**Logistic Regression** provides a simple linear baseline[cite: 10].

**k-Nearest Neighbors** classifies samples based on nearby examples in the feature space[cite: 10].

**Support Vector Machine** with an RBF kernel can model non-linear relationships between the extracted signal features[cite: 10].

**Gradient Boosting** uses a sequence of decision trees to gradually improve classification[cite: 10].

**Random Forest** combines many decision trees and can capture non-linear relationships and interactions between multiple features[cite: 10]. It also provides feature-importance values, which are useful for seeing which signal characteristics contribute most to the classification[cite: 10].

---

## Model Evaluation

Each original song produces many overlapping 5-second windows[cite: 10].

If these windows were randomly divided into training and testing sets, windows from the same song could appear in both sets[cite: 10]. The model could then learn characteristics specific to that recording instead of learning patterns that generalize to other songs[cite: 10].

To avoid this, I use **Stratified Group K-Fold cross-validation**[cite: 10].

All windows from the same song stay together in the same fold, so a song used for testing does not also appear in the training data for that fold[cite: 10].

The main metric used to compare the models is **Macro F1**, since the number of recordings is not balanced across all six genres[cite: 10].

## Results

| Model | Mean Macro F1 | Std. Dev. |
| :--- | :---: | :---: |
| **Random Forest** | **0.4726** | **± 0.0675** |
| Gradient Boosting | 0.4496 | ± 0.1026 |
| k-Nearest Neighbors | 0.3603 | ± 0.1099 |
| Support Vector Machine | 0.3145 | ± 0.1135 |
| Logistic Regression | 0.2590 | ± 0.0704 |

Random Forest achieved the highest mean Macro F1 score across unseen tracks[cite: 10].

Across all out-of-fold window predictions, the Random Forest model achieved **52.7% accuracy** (769 of 1,459 windows correctly classified)[cite: 10]. For comparison, random guessing across six classes corresponds to an accuracy of approximately 16.7%.

Modern Pop, R&B, and Rap showed the strongest classification performance in the dataset[cite: 8]. Country was the most challenging genre for the model to separate, often showing dynamic overlap with Electronic and Modern Pop tracks[cite: 8].

### Top Feature Importances (Gini Gain)

The ten most influential features identified by Random Forest were[cite: 8]:

1. `band_bass` (0.1485)
2. `log_bass_to_high` (0.1441)
3. `rms` (0.0815)
4. `energy_entropy` (0.0693)
5. `spectral_centroid` (0.0656)
6. `snr_db` (0.0641)
7. `max_amplitude` (0.0627)
8. `band_sub_bass` (0.0589)
9. `log_sub_to_mid` (0.0580)
10. `bpm` (0.0454)

Low-frequency physical vibrations (`band_bass` and `log_bass_to_high`) contributed the most to separating genres, as bass drum hits and sustained basslines create the largest mechanical deflections on the flexible sensor membrane.
