# Piezoelectric Music Classifier

## Background

This project comes from my undergraduate research at **Purdue University**, where I worked on fabricating piezoelectric sensors and analyzing the electrical signals they generated.

The main question I wanted to explore was:

**Can the electrical response from a piezoelectric sensor be used to tell different types of music apart?**

To test this, I fabricated the sensors, collected current signals while different songs were played, processed the signals in Python, and trained several machine-learning models to classify the music genre.

## Abstract

I fabricated **35 piezoelectric sensors** during this project. Out of those, **3 sensors produced stable and usable signals** for further experiments.

Using these sensors, I collected **26 music recordings across six genres**. The current generated by the sensor was measured using a low-noise current preamplifier and recorded through LabVIEW.

The raw signals were processed in Python using filtering, window segmentation, and feature extraction. Each signal window was converted into 19 numerical features and evaluated using five machine-learning models.

To prevent data leakage, windows from the same song were kept together during cross-validation.

Among the five models, **Random Forest achieved the highest mean Macro F1 score of 0.4726 ± 0.0675**. Across all out-of-fold predictions, it correctly classified **769 of 1,459 signal windows**, corresponding to an overall accuracy of **52.7%** (or **53.0%** rounded).

---

## Sensor Fabrication

The sensors were fabricated using a flexible **Ecoflex substrate**.

The main fabrication steps were:

1. Prepare the Ecoflex base.
2. Add the liquid-metal electrode/bar to the Ecoflex.
3. Soak the device in a solution containing `H2SO4`, `Zn(NO3)2·6H2O`, and `H2O`.
4. Leave the device in the solution for approximately **6 hours**.

A total of **35 sensors** were fabricated, and **3 produced stable enough responses** for the music experiments.

## Code Structure

The analysis is divided into five Python files inside the `Code/` folder:

- `labels.py` — assigns the genre and song ID from each filename
- `loader.py` — reads the LabVIEW data and preprocesses the current signal
- `features.py` — extracts numerical features from each signal window
- `dataset.py` — builds the machine-learning dataset
- `main.py` — trains and evaluates the classification models

---

## Signal Processing Pipeline

The raw LabVIEW current signal first goes through signal preprocessing:

1. The DC offset is removed, followed by a **0.5–450 Hz 4th-order Butterworth band-pass filter**.
2. Each recording is divided into **5-second windows with 50% overlap**.
3. Nineteen features are extracted from every window and passed to the machine-learning models.

The complete dataset contains:

- **1,459 signal windows**
- **26 original music recordings**
- **19 features per window**

The overall pipeline is:

**Raw LabVIEW signal → Preprocessing → 5-second windows → Feature extraction → Dataset construction → Grouped cross-validation → Model comparison → Genre prediction**

---

## Feature Engineering

For each 5-second signal window, I extract **19 features** that describe the amplitude, shape, timing, energy, and frequency distribution of the electrical signal.

### Amplitude and Energy

- RMS
- Maximum amplitude
- Crest factor
- Signal-to-noise ratio (referenced against calibrated baseline)
- Log total power
- Energy entropy

These features describe the overall strength and dynamic energy of the current signal.

### Signal Shape

- Skewness
- Kurtosis
- Zero-crossing rate

These features describe the symmetry and statistical distribution of the waveform.

### Pulse Timing

- BPM
- Tempo variation coefficient

These features are based on the spacing between detected electrical peaks above a 3-sigma noise threshold. The BPM value is treated as an estimate of the **electrical pulse rate**, rather than the exact musical BPM of the original song.

### Frequency-Domain Features

- Sub-bass band power: 5–35 Hz
- Bass band power: 35–100 Hz
- Mid-frequency band power: 100–250 Hz
- High-frequency band power: 250–450 Hz
- Sub-bass-to-mid ratio
- Bass-to-high ratio
- Spectral centroid
- Spectral flux

These features describe how the signal energy is distributed across different physical frequency ranges.

## Machine-Learning Models

I compared five machine-learning models:

- **Logistic Regression**: Provides a simple linear baseline.
- **k-Nearest Neighbors**: Classifies samples based on nearby examples in the feature space.
- **Support Vector Machine**: Uses an RBF kernel to model non-linear boundaries.
- **Gradient Boosting**: Uses shallow sequential decision trees to iteratively minimize loss.
- **Random Forest**: Combines decision trees to capture non-linear relationships and feature interactions, while providing feature-importance values.

---

## Model Evaluation

Each original song produces many overlapping 5-second windows. If these windows were randomly split into training and testing sets, windows from the same song would appear in both sets, causing data leakage.

To avoid this, I use **Stratified Group K-Fold cross-validation (5 splits)**. All windows from the same song stay together in the same fold, ensuring the model is strictly evaluated on unseen tracks.

The primary metric used to compare models is **Macro F1**, since the class distribution is imbalanced.

## Results

### Leaderboard

| Model | Mean Macro F1 | Std. Dev. |
| :--- | :---: | :---: |
| **Random Forest** | **0.4726** | **± 0.0675** |
| Gradient Boosting | 0.4496 | ± 0.1026 |
| k-Nearest Neighbors | 0.3603 | ± 0.1099 |
| Support Vector Machine | 0.3145 | ± 0.1135 |
| Logistic Regression | 0.2590 | ± 0.0704 |

Random Forest achieved the highest mean Macro F1 score across unseen tracks. 

Across all pooled out-of-fold window predictions, the model achieved **52.7% accuracy** (769 of 1,459 windows correctly classified), compared to a 16.7% random-chance baseline across six classes.

### Performance by Genre (Random Forest)

| Genre | Precision | Recall | F1-Score | Support |
| :--- | :---: | :---: | :---: | :---: |
| Country | 0.21 | 0.21 | 0.21 | 304 |
| Electronic | 0.55 | 0.58 | 0.57 | 369 |
| Modern Pop | 0.71 | 0.79 | 0.75 | 234 |
| Piano | 0.48 | 0.41 | 0.44 | 268 |
| R&B | 0.70 | 0.63 | 0.66 | 198 |
| Rap | 0.74 | 0.79 | 0.76 | 86 |
| **Macro Average** | **0.57** | **0.57** | **0.57** | **1,459** |

Modern Pop, R&B, and Rap showed the strongest classification performance. Country was the most difficult genre for the model to distinguish and was frequently confused with Electronic and Modern Pop due to broad spectral overlap.

### Top Feature Importances (Gini Gain)

1. `band_bass` (0.1485)
2. `log_bass_to_high` (0.1441)
3. `rms` (0.0815)
4. `energy_entropy` (0.0693)
5. `spectral_centroid` (0.0656)
6. `snr_db` (0.0641)
7. `max_amplitude` (0.0627)
8. `band_sub_bass` (0.0589)
9. `log_sub_to_mid` (0.0580)
10. `bpm` (0.0454)

Low-frequency energy (`band_bass` and `log_bass_to_high`) contributed the most to genre separation, as bass drum transients and low-frequency components produce the largest mechanical deflections on the flexible sensor film.
